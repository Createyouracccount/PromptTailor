# 루프 프로토콜 세팅

GOAL(원문): "$ARGUMENTS"

## 지시

0. **스케일 게이트**: GOAL이 1회성 소규모 작업(단일 파일 수정, 단일 함수 작성, 단순 질문)이면 루프를 만들지 마라. "이 규모는 루프가 아니라 `/prompt-tailor:pm` 감입니다"라고 한 줄로 안내하고 멈춰라. 루프는 여러 라운드에 걸쳐 개선·검증을 반복할 목표에만 쓴다.

1. **원칙 추출**: 현재 대화와 로드된 메모리에서 사용자가 명시했거나 반복 확인한 작업 원칙을 추출하라. 각 원칙에 근거(사용자 발언 요지 또는 메모리 출처)를 한 줄씩 붙여라. **대화에 근거가 없는 원칙을 지어내지 마라** — 부족하면 아래 기본 골격에서 가져오되 각 항목에 [기본값]을 표시하라.
   - 기본 골격: 작은 단위 변경→검증→커밋 반복 / 주장은 실측 증거로만 / 부정적 결과도 기록·공개 / 판정 기준은 작업 **전에** 확정하고 동결 / 라운드마다 원장 기록 / 실패 판정 문구를 미리 마련("안 됐다"가 정당한 결론이 될 자리).

2. **프로토콜 파일 생성** — 대상 프로젝트 루트에. **기존 파일이 있으면 덮어쓰지 말고**, 있다는 사실을 보고하고 재사용·이어쓰기를 제안하라:
   - `LOOP_LOG.md` — 원장. 헤더: 라운드마다 최상단에 1개 항목(날짜·라운드 / 완료 / 실측 증거 / 발견 문제 / 다음 인수 지점). 이 파일이 세션 간 인수인계의 단일 원장이다.
   - `GATES.md` — GOAL에서 도출한 통과/중단 기준 **초안**. 각 게이트는 ① 측정 방법 ② 숫자 임계 ③ 판정 템플릿(PASS / FAIL / PARTIAL — 각각 어떤 문장으로 보고할지 리터럴로)을 갖출 것. 상단에 GOAL 원문을 그대로 인용하고, **동결 조항**을 명시하라: "이 기준은 사용자 승인 없이 변경할 수 없다." 진행 지표는 의견이 아니라 숫자로(남은 실패 테스트 수, 남은 가정 수, 남은 TODO 수 — 래칫: 뒤로 갈 수 없게).

3. **라운드 구조 제시**: 발굴(문제 1개) → 최소 변경 → 실측 검증(숫자) → 커밋(작게) → 원장 기록. 검증 강도는 규모에 비례시켜라 — 사소한 수정은 판정 템플릿만, 중요한 주장(성능·보안·"놀라운" 결과)에는 fresh-context 심판을 반증 프레임으로 붙여라.

4. **동결 승인**: 게이트 초안을 사용자에게 보여주고 승인을 받아 동결한 **뒤에** 라운드 1을 시작하라. 승인 전에 실행 작업을 시작하지 마라.

5. 이 명령은 LLM 재작성 백엔드를 호출하지 않는다 — 원칙 추출과 프로토콜 작성은 대화 맥락을 가진 현재 모델(너)의 몫이다.
